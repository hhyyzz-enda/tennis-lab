# Tennis Lab 前端答辩说明（代码组织 / 选型 / 功能与效果）

> 项目定位：以“网球学习与训练辅助”为主题的单页应用（SPA），覆盖内容科普、课程体系、AI 辅助训练、社区论坛、教练反馈与私信等功能。

## 1. 技术栈与选型理由

### 1.1 核心框架

- Vue 3（SFC 单文件组件）
  - 组件化与响应式机制成熟，适合页面模块多、交互密集的学习型网站。
  - 代码组织上天然按“页面（views）/组件（components）/服务（services）”划分，答辩讲解成本低。
  - 本项目多数页面使用 Options API（data/computed/methods），更贴近传统 MVC 思维，便于团队协作与快速上手；少量高交互组件使用 `<script setup>` 提升可维护性与逻辑内聚。

- Vite
  - 开发阶段 HMR 快、启动快；生产构建支持代码分割与静态资源优化。
  - 配置相对轻量，适合答辩展示与二次迭代。

### 1.2 路由与国际化

- vue-router
  - SPA 必需：页面级切换、动态参数（如课程/帖子/教练详情）与滚动行为控制。
  - 路由组件使用动态 import，实现按路由懒加载，降低首屏体积。

- vue-i18n
  - 统一文案来源，支持中英双语切换，适合面向不同用户群的展示。
  - 使用 legacy 模式，兼容 Options API 的 `$t()` 直接调用。

### 1.3 UI 组件库（混用的原因）

项目依赖同时包含：
- Element Plus：表单/输入/日期选择器/消息提示更完善，适合登录注册与信息编辑场景。
- Arco Design Vue：按钮、图标等轻量场景接入成本低，视觉风格统一性较好。
- Naive UI：卡片类布局组件（如 NCard）在会员入口/导航卡片上使用更方便。

说明：该项目采用“按需选用”的策略，不强行将全部页面绑定到单一 UI 库，从而更快拿到可用组件并聚焦业务；同时通过页面级 scoped CSS 把整体视觉收敛到同一套风格。

### 1.4 样式与工程化

- scoped CSS + 全局基础样式
  - 大多数页面使用 `style scoped`，把样式约束在组件内，避免全局污染。
  - 全局层面提供了基础 reset 与滚动行为统一（见 `src/assets/main.css`）。
- PostCSS（autoprefixer）确保多浏览器兼容。
- TailwindCSS 已加入构建链路（`postcss.config.js` / `tailwind.config.js`），当前页面主要以手写 CSS 为主（Tailwind 内容扫描未配置，属于可扩展点）。

## 2. 代码组织架构（目录结构与职责）

项目根目录：`tennis-lab/`

```
tennis-lab/
  src/
    main.js                # 应用入口：createApp + i18n + router
    App.vue                # 应用壳：顶栏/移动端菜单/语言切换/页脚/RouterView
    router/index.js        # 路由表 + scrollBehavior
    i18n/index.js          # i18n 初始化（zh-CN/en-US）
    locales/               # 文案字典
    assets/                # 图片、全局 CSS、背景图等静态资源
    mock/                  # 本地 mock 数据与动作分析 JSON
    services/              # API 请求封装与数据归一化
    views/                 # 页面级组件（路由组件）
    components/            # 可复用组件（训练动画/分析面板等）
  public/                  # 静态资源（原样拷贝到产物）
  vite.config.js           # Vite 配置与别名
  package.json             # 依赖与脚本
```

### 2.1 页面层（views）

- `src/views/*View.vue`：每个路由对应一个页面组件，负责：
  - 页面布局与交互状态（loading/error/分页/筛选等）
  - 组合业务组件（如 AI 训练的呼吸训练与关节分析）
  - 调用 services 获取数据并渲染

### 2.2 组件层（components）

- `src/components/*`：抽象可复用交互/动画/可视化能力，典型包括：
  - `BreathTrainingOrb.vue`：呼吸训练引导 + 倒计时 + 回合流程（定时器驱动的交互状态机）。
  - `JointForceAnalysis.vue`：基于 JSON 数据的关节发力条形图 + 运动链 SVG 可视化（requestAnimationFrame 播放）。
  - `PlayCountdownOverlay.vue`：统一倒计时遮罩层。

### 2.3 服务层（services）

- `src/services/*.js`：统一处理“请求 + 鉴权头 + 错误处理 + 数据归一化”，页面层只关心业务字段。
- 多数服务使用原生 `fetch`，减少 axios 等额外依赖；并且在函数内进行：
  - `code === 200` 的业务码解包
  - 错误信息兜底（message/msg/error）
  - token 注入（统一 `satoken: Bearer ...`）

### 2.4 数据层（mock + 环境变量）

- `src/mock/*`：
  - 课程列表（premiumCourses / tennisAiCourses）
  - 技术动作分析数据（如发球、反手等 JSON）
- `VITE_TENNIS_DATA_SOURCE=mock/api`：用于切换使用 mock 还是后端 API（例如 `premiumCourseService.js`）。

## 3. 应用入口与“壳”设计

### 3.1 应用启动流程

- `src/main.js`
  - 引入全局样式 `src/assets/main.css`
  - `createApp(App).use(i18n).use(router).mount('#app')`

### 3.2 App.vue 的职责

- 顶部导航（桌面端/移动端）：
  - `RouterLink` 跳转主要功能模块
  - 移动端通过 `transition` 实现菜单淡入淡出
- 登录态感知：
  - 读取 `localStorage.tennisLabAuth`（见 `getStoredAuthToken()`）
  - 监听 `storage` 与自定义事件 `tennislab-auth-changed`，实现多标签页同步与组件间同步
- 语言切换：
  - 直接设置 `this.$i18n.locale`
- 页脚显示策略：
  - 根据 route name 控制页脚是否显示（例如资源页/课程页可隐藏，减少信息干扰）

## 4. 路由设计（模块化 + 懒加载）

路由文件：`src/router/index.js`

关键点：
- 路由组件均为动态 import（`component: () => import(...)`）
  - 生产构建时自动分包，提升首屏加载速度。
- 支持 hash 锚点滚动（首页 featured/contact）
  - `scrollBehavior` 对 hash 设置 `top` 偏移，避免被顶栏遮挡。
- 动态参数路由：
  - `/tennis-ai/courses/:slug`（AI 课程详情）
  - `/premium-courses/:id`（精品课程详情）
  - `/tennis-forum/:id`（论坛帖子详情）
  - `/training-feedback/coaches/:id`（教练详情）
  - `/messages/:contactId`（私信会话）

## 5. 国际化（i18n）

入口：`src/i18n/index.js` + `src/locales/zh-CN.js` / `src/locales/en-US.js`

- 统一用 `$t('...')` 获取文案，保证：
  - 组件内部不硬编码大段文本
  - 页面结构与文案可独立演进
- 对“数据字段是多语言对象”的情况，页面提供 `localize()` 方法：
  - 优先取当前语言，fallback 到中文（示例：课程标题/简介）

## 6. 鉴权与权限体验（前端实现）

### 6.1 Token 存储与读取

- token 存在 `localStorage.tennisLabAuth`（JSON，内部可能包含 token 与 user 信息）
- `authService.js` 提供 `getStoredAuthToken()`：
  - 解析存储结构，兼容不同后端返回格式
  - 统一注入请求头 `satoken: Bearer <token>`

### 6.2 权限控制策略（页面内控制为主）

项目没有强依赖“全局路由守卫”，而是采用页面内控制：
- 需要登录的页面/区域（聊天、AI 历史、教练私信等）：
  - 未登录：展示提示 + 跳转登录按钮
  - 已登录：展示内容并加载数据
- 登录页支持 redirect：
  - 例如个人信息页跳转登录时带上 `?redirect=`，便于登录后回跳

这种策略的好处：
- 逻辑贴近业务 UI，不会出现“硬拦截导致用户不知道发生了什么”的体验问题。

## 7. API 与数据流（services 设计）

### 7.1 通用模式

以 `authService.js` / `chatService.js` / `trainingPlanService.js` 为例：
- 拼接 baseUrl：支持 `.env` 覆盖 + 默认回退地址
- `parseJsonSafely()`：避免后端返回空字符串或非 JSON 导致崩溃
- `unwrapBusinessPayload()`：将 `code !== 200` 统一转为异常，页面用 try/catch 控制 error UI

### 7.2 Mock 与 API 的双通道

以 `premiumCourseService.js` 为例：
- `VITE_TENNIS_DATA_SOURCE !== 'mock'` 时走后端 API
- 否则读取 `src/mock/premiumCourses.json`
- 同时对后端字段做归一化（cover/images/title/intro/modules 等），保证页面渲染模型稳定

## 8. 关键页面与功能实现（按模块讲解）

### 8.1 首页（HomeView）

- 背景轮播：定时器切换 `currentHeroIndex`，配合 CSS `opacity transition` 实现淡入淡出。
- Featured 卡片分页：
  - `featuredPageSize` 控制每页数量
  - 越界点击触发“边缘抖动”提示（shake-left/right）
- 登录欢迎浮层：
  - 登录成功后写入 `sessionStorage.tennisLabShowWelcomeOnce`
  - 首页读取并用 `<transition>` 做一次性浮动欢迎动画

### 8.2 登录注册（AuthView）

- 两层模式切换：
  - 登录/注册切换
  - 登录内部：密码登录 / 邮箱验证码登录
- Element Plus 组件：
  - `ElInput / ElButton / ElDatePicker / ElMessage`
- 关键交互：
  - 邮箱验证码发送后倒计时（`codeCountdown` + timer）
  - 输入清洗：去空格、密码去中文字符等（降低后端校验失败概率）
  - 登录成功后触发欢迎标记（给首页浮层用）

### 8.3 我的网球（MyTennis / Profile / Courses）

- MyTennisView：入口卡片（Naive UI NCard）作为“功能导航页”
- MyTennisProfileView：
  - 获取用户信息并展示（dl 列表）
  - `details/summary` 折叠表单：更新个人信息、修改密码
  - 统一表单校验与 ElMessage 提示
- MyTennisCoursesView：
  - 拉取“已加入课程”列表，支持分页切换
  - 点击进入精品课程详情

### 8.4 精品课程（PremiumCourses / Detail）

- PremiumCoursesView：
  - 类型 tabs + 搜索关键字
  - 分页器（含省略号）控制大页数场景可读性
- PremiumCourseDetailView：
  - 视频播放：`<video controls>`（若无 videoUrl 展示占位文案）
  - “加入我的课程”：调用 service 写入后端/本地，并用 `Teleport + Transition` 做居中 toast

### 8.5 AI 课程（Intro / Courses / Detail）

- TennisAiIntroView：
  - 进入引导弹窗（mask + 两个 action），引导用户先学基础/直接进入 AI 课程
- TennisAiCoursesView：
  - 课程卡片网格 + 关键字过滤（标题/副标题/难度）
- TennisAiCourseDetailView（亮点页面，适合答辩重点讲）
  - 顶部 jump-nav：按钮切换“介绍 / 呼吸 / 分析 / 联合训练”
  - 呼吸训练：`BreathTrainingOrb`（定时器驱动的流程引导 + 倒计时 + 回合统计）
  - 关节分析：`JointForceAnalysis`
    - 基于 JSON 动作数据绘制条形图与 SVG 运动链
    - 通过 requestAnimationFrame 播放，支持不同速度档位
  - 联合训练（combo）：
    - 父组件通过 ref 调用子组件公开方法，实现“先倒计时，再同时开始两种训练”的编排

### 8.6 AI 训练计划（AiTrainingPlanView）

- 两个任务页签：器材推荐 / 训练计划（表单输入）
- 表单校验：
  - 身高/体重/频率/周期等字段做整数输入清洗与 blur 校验
  - 预算字段支持更宽松输入并给出提示
- 结果展示：
  - `<pre>` 输出 AI 文本结果，保留格式便于阅读
- 历史记录：
  - 拉取历史列表 + 分页
  - 点击详情弹出遮罩层（自实现 modal），展示完整响应内容

### 8.7 论坛（TennisForum / Detail）

- TennisForumView：
  - 帖子列表加载 + 点击进入详情
  - “发布面板”可折叠：标题/内容/标签校验
  - 后端错误兜底：遇到 Internal Server Error 给出更友好的提示

### 8.8 教练反馈与私信（TrainingCoaches / CoachDetail / Messages）

- TrainingCoachesView：
  - 教练列表卡片，点击进入详情
- TrainingCoachDetailView：
  - 教练资料展示（基础信息/联系方式）
  - 登录后可直接给教练发私信，并展示与该教练的历史消息
- ChatMessagesView：
  - 拉取全量消息后，在前端按“联系人”聚合成会话列表
  - 进入会话后显示消息气泡，并根据时间间隔插入时间分隔条
  - 发送消息后自动刷新并回到最新会话状态

### 8.9 学习资源导航（TennisResourcesView）

- 资源按主题分区（官方/大满贯/比分/新闻/数据/社区/装备等）
- 关键交互：
  - 搜索关键词过滤分区与链接
  - 动态显示网站 favicon（失败时回退到本地默认图标）
  - 滚动监听：出现“回到顶部”按钮

### 8.10 外部课程（ExternalCoursesView）

- 本地静态数据列表（包含封面、平台、课程优势、外链）
- 分类 tab + 关键词搜索 + 分页
- 全量 i18n：数据字段以 `{ 'zh-CN': ..., 'en-US': ... }` 存储，页面用 `localize()` 渲染

### 8.11 Developing Letter（DevelopingLetterView）

- 打字机效果：
  - `typedLength` 逐字递增，配合 blinking caret
  - 弹层带“纸张展开”动画（CSS keyframes）

## 9. 视觉效果与交互实现总结（可用于答辩强调）

- 统一的“沉浸式背景”方案：多个页面使用 `::before/::after` 固定背景图 + 渐变遮罩，保持内容可读性且风格统一。
- 动画与过渡：
  - `<transition>`：菜单、浮层、toast、页面内部卡片切换
  - CSS keyframes：打字光标、纸张展开、浮动欢迎字等
- 可视化交互：
  - `JointForceAnalysis` 使用 SVG + 动画播放，属于“可答辩重点亮点”
- 响应式：
  - 大量 `@media` 断点，保证移动端导航与卡片列表布局可用
- 可访问性（a11y）：
  - 按钮/导航添加 `aria-label`，弹层 `role="dialog"`，列表中可键盘触发（enter/space）

## 11. 可扩展点（答辩可作为“后续优化方向”）

- 统一 UI 组件库（当前混用可工作，但后续可以归一化组件与主题）
- Tailwind content 配置补全，使其真正参与样式生成（或移除以精简依赖）
- 路由守卫与权限策略进一步抽象（例如封装 `requireAuth` 高阶组件/指令）
- 服务层公共化（auth/chat/ai 等 service 里有重复的 parse/headers 逻辑，可抽成 `request.ts` 风格的统一封装）
